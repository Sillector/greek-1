# Правило согласованности: текст ↔ сцена

Это игра для заучивания слов: значение слова игрок выводит из того, что **видит**. Если повар говорит «зал маленький, а кухня большая», а в сцене наоборот — игрок выучит неправду. Поэтому:

1. Каждое слово, которое проверяется глазами, помечено в `words` полем `claimKind` (`size`, `price`, `near`, `place`, `color`, `count`, `time`). Цвета (κόκκινος, μπλε…), размеры, цены, «рядом/далеко» — всегда.
2. Каждая фраза с таким словом (реплика, табличка, просьба, строка главной задачи) обязана иметь утверждение в `claims` с её адресом в `src` и словом в `words`. Нет утверждения — `validate` шаг (7) красный.
3. Каждое утверждение проверяется по сцене числами (те же координаты и габариты моделей, что строит движок — `engine/js/layout.js` + `assets/catalog.json`).
4. Где расходится — правим **сцену** (переставить, увеличить, добавить ценник/предмет), текст меняем только если сцену так не построить.

## Адреса фраз (`src`)
`npc:<id>:<номер реплики с 0>`, `sign:<id>:<строка>`, `quest:<id>` (вся просьба), `mystery:<строка>`, `finale:<номер>`.

## Типы утверждений

| type | ключи | проходит, если |
|---|---|---|
| `size` | `subject`, `is: small/big`, `vs[]`, `metric` (area/height/width) | small: subject ≤ 0.85 × каждого из vs; big: ≥ 1.15 × каждого |
| `bigger` | `a`, `b`, `by` (во сколько раз, по умолч. 1.3), `metric` | a ≥ by × b |
| `near` / `far` | `a`, `b`, `max` / `min` (м, по умолч. 20 / 25) | расстояние между краями ≤ max / ≥ min |
| `price` | `item` (`prop:<id>` ценника с `value` или `sign:<id>:<строка>` с «N €»), `word: cheap/expensive`, `max`/`min` | цена ≤ max (дёшево) / ≥ min (дорого) |
| `at` | `npc`, `area` (`<интерьер>.<часть>`) или `zone` | житель стоит в этой части/зоне |
| `has` | `ref`: `prop:<id>` (+`zone`), `tag:<тег каталога>` (+`zone`), `backdrop:<kind>` | предмет/модель с тегом/фон есть |
| `schedule` | `sign`, `day` (id слова-дня), `open` | строка таблички с этим днём: «—»/κλειστ… = закрыто, часы = открыто |
| `time` | `value` (day/evening/night) | время суток мира |
| `color` | `ref` (`prop:<id>`), `color` (red, orange, yellow, green, blue, purple, pink, white, gray, black) | цвет предмета: `color` у процедурного (`boat`, `pile`, `building`, `box`…) или `color` модели в `assets/catalog.overrides.json` |
| `offscreen` | `note` (обязательно) | не проверяется сценой — то, чего игрок не видит (цены в далёком городе). Используйте редко и честно объясняйте в `note` |

Ссылки на места: `zone:<id>` (для интерьера — его дверь снаружи; для открытой зоны расстояние считается от края), `prop:<id>`, `npc:<id>`, `area:<интерьер>.<часть>` (из `areas` интерьера).

## Пример — повар и кухня
```json
"areas": [{ "id": "hall", "rect": [-4.7, 0, 3.6, 9] }, { "id": "kitchen", "rect": [1.8, 0, 9.4, 9], "floor": "tiles" }]
...
{ "id": "kitchen-big", "type": "bigger", "a": "area:estiatorio.kitchen", "b": "area:estiatorio.hall", "by": 2,
  "src": ["npc:nikos:4"], "words": ["megalos", "mikros"] }
```
Поменяй местами размеры зала и кухни — `validate` ответит: `утверждение kitchen-big: area:estiatorio.kitchen = 32.4, area:estiatorio.hall = 84.6 — нужно в 2 раза больше`.

## Чего числа не ловят
Как это выглядит: зал может быть «маленьким» по площади, но заставленным так, что кажется большим. Поэтому после зелёного `validate` — `tools/shot.mjs` и взгляд на снимки (см. скил make-quest, шаг «снимок → правка»).
